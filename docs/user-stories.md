# User Stories

기술 구현은 개발 쪽이 애자일하게 정한다. 이 문서는 **누가 무엇을 원하고, 어떤 결과면 끝인지**만 정의한다. AC 번호는 `spec.md`의 합격 기준을 가리킨다.

## 사용자

| 이름 | 누구 | 목표 |
|---|---|---|
| **리뷰어** | 링크를 여는 VC·심사위원 | 설치·로그인 없이 90초 안에 "눈치 있는 캐릭터"를 체험하고 가치를 판단한다 |
| **마야 (가칭)** | 미국 클라이언트와 일하는 프리랜서 디자이너. 영어로 일한다. 데모 페르소나 | 일하는 중에 방해받지 않고, 필요한 순간에만 도움받는다 |

데모에서 리뷰어는 마야의 입장이 되어 체험한다. 마야의 메일·일정·파일은 모두 가공 데이터다.

## 우선순위

- **Must**: 데모가 성립하려면 반드시 필요 (M)
- **Should**: 시간이 되면 (S)
- **Could**: 시간이 남을 때, 가장 먼저 자른다 (C)

## 데모 시나리오 (리뷰어 90초)

각 단계는 `user-flow.md`의 단계 번호와 연결된다.

| 시간 | 리뷰어의 경험 | 관련 스토리 |
|---|---|---|
| 0–10초 | 링크를 열면 캐릭터가 인사하고 한 줄 설명이 보인다 | US-1 |
| 10–25초 | 안내문을 읽고 데모 메일 탭을 공유한다. 오른쪽 하단에 공유 중 표시가 뜬다 | US-3, 4, 5 |
| 25–45초 | 영어 메일을 읽는다. 캐릭터는 곁눈질만 하고 말이 없다. 타이핑하자 계속 조용하다 | US-8, 11 |
| 45–60초 | 멈춘 지 20초 뒤 "답장 초안 써 줄까?" 확인 카드가 뜬다. 수락한다 | US-7, 12 |
| 60–72초 | 초안이 저장되고 내용이 보인다. "발송은 네가 직접 해" | US-15, 16 |
| 72–85초 | 오후 3시 일정 충돌 경고가 나온다 | US-17 |
| 85–90초 | 호감도가 오르고 해금될 의상이 예고된다 | US-28 |

## 하지 않을 것 (스토리로 만들지 않음)

로그인·계정 연결(리뷰어), 메일 발송, 삭제, 결제, 입력 자동 조작, 연애·성인 요소, 데스크톱 앱.
