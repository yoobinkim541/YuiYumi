# User Stories

기술 구현은 개발 쪽이 애자일하게 정한다. 이 문서는 **누가 무엇을 원하고, 어떤 결과면 끝인지**만 정의한다. AC 번호는 `spec.md`의 합격 기준을 가리킨다.

## 사용자

| 이름 | 누구 | 목표 |
|---|---|---|
| **리뷰어** | 링크를 여는 VC·심사위원 | 설치·로그인 없이 90초 안에 "눈치 있는 캐릭터"를 체험하고 가치를 판단한다 |
| **사용자** | 컴퓨터로 일하는 평범한 사람. 특정 직업이 없다(범용). 메일·일정·문서를 쓰고, 가끔 외국어 메일을 받는다. 한·중·일·대만 시장의 누구나 해당 | 일하는 중에 방해받지 않고, 필요한 순간에만 도움받는다 |

데모에서 리뷰어는 사용자의 입장이 되어 체험한다. 메일·일정·파일은 모두 가공 데이터이며, 특정 직업을 떠올리게 하지 않는 일상적인 내용으로 구성한다.

## 우선순위

- **Must**: 데모가 성립하려면 반드시 필요 (M)
- **Should**: 시간이 되면 (S)
- **Could**: 시간이 남을 때, 가장 먼저 자른다 (C)
