Bloom x Anthropic x Seoul AI Hub | Ambition for Korea 해커톤 (2026-10-24)

서비스 이름은 **YuiYumi(유이유미)**로 확정한다. (이전 가칭 Nunchi는 컨셉 이름 "눈치"로만 남긴다.)

## 주제 선언

**김&양 · 한국의 엔터·게임 감각으로 미국 Personal Agent와 겨루는 서비스**

화면 위에 상주하며 내가 하는 일을 보고 먼저 말을 걸고, 메일·일정 같은 업무를 대신 처리해 주는 Live2D 캐릭터 AI 비서.

- **미션 연결**: AttentionX "한국의 엔터·게임 감각으로 미국 Personal Agent와 경쟁하는 서비스". 미국 Personal Agent는 기능은 강하지만 정이 없다. 우리는 한국의 캐릭터·엔터 감각(Live2D, 호감도, 눈치)으로 겨룬다.
- **타깃**: 서브컬처 문화가 강하고 컴패니언 앱 Zeta의 큰 시장인 **일본·대만**, 그리고 제품의 출신지이자 심사 시연 언어인 **한국**을 첫 출시로 한다. **중국 본토는 확장 시장**이다. (Zeta 시장 규모는 Notion 출처 목록의 기사 기준이며 직접 검증하지 않았다.)
- **"화면 위에 상주"는 웹 버전에서는 페이지 안 상주**로 구현한다. 바탕화면 위 오버레이는 브라우저 제약과 설치 위험 때문에 로드맵이다. 제출 문구는 "데모는 웹, 상주형 오버레이는 다음 단계"로 정직하게 쓴다.
- **중국 본토를 확장 시장으로 둔 이유**: Google 서비스는 중국 본토에서 쓸 수 없고, Anthropic API는 중국 본토가 공식 지원 지역이 아닌 것으로 알고 있다(둘 다 현재 공식 문서 확인 필요). 현지 서비스·모델 대응이 필요하다고 설명한다. 화면 인식은 어떤 앱이든 읽으므로 특정 서비스 연동에 의존하지 않는다는 점이 강점이다.

## 한 줄 정의

일하는 동안 옆에서 눈치껏 한마디 하고, 시킨 일은 초안까지 해두는 캐릭터.

컴패니언은 정은 있지만 일을 못 하고, 에이전트는 일은 하지만 정이 없다. 캐릭터가 일의 맥락을 읽는 능력(눈치)으로 정을 만든다. 연애·성인 요소 없음, 일 잘하는 같은 팀 동료.

## 제품 형태

- **웹(심사 링크)**: 링크만 열면 데모가 완결된다. 웹은 브라우저 제약상 바탕화면 위 투명 오버레이가 불가능(Document PiP는 타이틀바 고정·크기 상한·창 1개·투명도 미지원)하므로, 페이지 안에 캐릭터를 띄우고 데모용 화면을 함께 보여 준다.
- **서버(`api/`)**: Claude, ElevenLabs, 눈치 게이트, 데모 계정 커넥터. 키와 토큰은 서버에만 둔다.

### 스택: AIRI 포크

`moeru-ai/airi`를 직접 확인한 결과:

- 라이선스 MIT, TypeScript pnpm 모노레포(`packageManager: pnpm@11.24.0`), 활성 프로젝트
- `apps/stage-web`은 Vue 기반 Vite 앱이며 Live2D·3D, 음성 파이프라인 관련 패키지가 의존성에 있다. 배포 설정(`netlify.toml`, `wrangler.toml`, `Dockerfile`)이 있고 정적 SPA다.
- 레포가 약 590MB로 크므로 `git clone --depth 1`로 받는다.

**미확인(포크 작업 중 확인)**: Claude·ElevenLabs 내장 여부, 웹판의 실제 동작 범위, 화면 인식 유무, 빌드 난이도.

**시험 기준**: `pnpm i && pnpm dev`로 stage-web이 **30~40분 안에** 뜨면 진행하고, 못 뜨면 즉시 접고 Vue 없이 직접 구현으로 돌아간다. 이 PC에는 pnpm이 없으므로 `corepack enable`부터 확인한다.

**키 프록시(가장 중요한 수정)**: AIRI는 사용자가 브라우저에 키를 입력하는 BYOK 구조일 가능성이 높다(미확인). 공개 데모에서는 키가 노출되면 안 되므로 LLM·STT·TTS 호출 경로를 우리 서버 프록시(`api/`)로 바꾼다.

**출처 표기**: 제출물과 발표에 "AIRI(MIT) 기반, 눈치 엔진·업무 도구·확인 UX·화면 인식·데모 계정 연동은 자체 구현"이라고 밝히고, `LICENSE`와 저작권 고지를 유지한다.

## 눈치 엔진

입력: 같은 화면 체류 시간, 화면 내용(비전), 마지막 끼어들기 후 경과 시간, 오늘 끼어든 횟수, 사용자 발화 여부.

1. **규칙 게이트(결정적, LLM 호출 전)**: 하루 3회 초과, 마지막 끼어들기 후 10분 이내, 같은 화면 체류 20초 미만, 사용자가 "조용히" 설정, 사용자가 말하는 중이면 침묵
2. **판단(Haiku 비전, 짧은 JSON)**: `{speak, reason, line, offer}`
3. **실행(Sonnet 또는 Opus tool use)**: 사용자가 확인 카드를 수락한 경우에만. 어느 모델을 쓸지는 아래 "모델 구성"의 라우팅이 정한다.

## 모델 구성

| 역할 | 모델 | 하는 일 |
|---|---|---|
| 눈 + 라우터 | **Haiku** | 공유된 화면을 계속 관찰하고, 말을 걸지 판단하고, 사용자 요청이 오면 종류와 실행 모델을 고른다 |
| 기본 작업 | **Sonnet** | 답장 초안, 일정 확인 등 일반 업무 |
| 어려운 작업 | **Opus** | 길고 복잡한 요청에만 예외적으로 |

모델 ID는 환경변수로 바꿀 수 있게 둔다(현재 `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`).

**요청 처리 흐름**

```
화면 관찰(Haiku) ─ 말 걸 만함 ─> 캐릭터가 먼저 제안
사용자 요청(말/글) ─> Haiku가 현재 화면과 함께 분류 {kind, emotion, confidence}
   kind=companion → 미리 만든 캐릭터 애니메이션을 재생한다(모델 생성 호출 없음)
   kind=task      → Sonnet이 수행
   kind=heavy     → Opus가 수행
결과 → (쓰기 작업이면 확인 카드) → 출력(말풍선, 소리가 켜져 있으면 음성도)
```

**규칙**

- 기본은 Sonnet이다. Opus는 복잡한 요청에만 쓰고 **일일 호출 상한**을 둔다(예산 보호).
- **데모 시나리오는 Sonnet으로 고정**한다. 지연과 비용을 예측할 수 있고 매번 같은 품질로 재현된다.
- 라우팅은 사용자 요청 때만 일어나며, 요청마다 Haiku 호출 1회가 추가된다.

**컴패니언 반응 (업무가 아닌 호출)**

무의미한 농담, 심심해서 부르기, 인사·칭찬·투정처럼 **작업·리서치·비서 업무가 아닌 컴패니언 역할의 요청**은 Haiku가 `companion`으로 분류한다. 이때는 Sonnet·Opus를 호출하지 않고 **이미 만들어 둔 애니메이션**(표정·모션)을 재생한다.

- Haiku는 분류와 감정 태그(neutral·happy·thinking·surprised·sorry·focused 중 하나)만 낸다. 어떤 애니메이션을 틀지는 **반응 라이브러리**에서 태그와 상황으로 고른다.
- 반응에 짧은 대사를 붙일 수 있다. 대사는 **미리 정해 둔 문장 풀**(한·일·중 번체)에서 고르고, 소리가 켜져 있으면 **미리 녹음한 음성 파일**을 쓴다. 이러면 생성 비용과 음성 합성 비용이 들지 않고 지연도 없다.
- 효과: 가벼운 상호작용은 거의 무료이고, 엔터·게임 같은 반응성(호감도, 모션)이 살아난다. 업무 호출만 비싼 모델을 쓴다.
- **오분류 방지**: 분류 확신이 낮거나 업무일 가능성이 있으면 `task`로 보낸다. 진짜 요청이 잡담으로 처리되는 것이 호출 비용보다 더 나쁘다.
- 같은 반응이 반복되지 않도록 쿨다운과 변주(같은 감정 태그의 여러 모션)를 둔다. 반응 연타로 호출이 쌓이는 것을 막는 상한도 둔다.
- 반응 라이브러리의 목록(트리거 종류 → 감정 → 모션·표정 → 대사)은 기획에서 정의하고, 보유한 Live2D 모델이 제공하는 모션·표정 이름과 매핑한다.

**"계속 관찰"의 비용 관리**

- Haiku가 고정 주기로 계속 호출되는 구조는 피한다. 브라우저에서 화면 변화와 체류 시간을 먼저 계산하고, **변화가 있고 규칙 게이트를 통과할 때만** 호출한다.
- 세션당 비전 호출 상한을 둔다. 탭이 숨겨졌거나 화면이 오래 안 바뀌면 관찰을 멈춘다.
- 심사자 여러 명이 동시에 열면 같은 키에서 차감되므로, 서버 일일 상한은 예약분 $150 이하로 건다.
- 예상 호출량과 단가는 현재 가격표로 계산해 둔다(여기서는 숫자를 가정하지 않는다).

## 출력: 소리와 텍스트

- **텍스트(말풍선)는 항상 표시**한다. 소리는 그 위에 더하는 선택 기능이다.
- **컴퓨터의 소리가 켜져 있는지는 브라우저가 알려 주지 않는다**(음소거·볼륨 상태는 웹에서 읽을 수 없는 것으로 알고 있다. 구현 때 확인). 그래서 자동 감지 대신 **사용자 토글(소리 켜기/끄기)**로 한다.
- 시작 화면에서 소리 켜기/끄기를 고르게 하고, 그 클릭이 브라우저 자동재생 정책이 요구하는 사용자 동작도 겸한다. 데모 화면에서도 언제든 바꿀 수 있다.
- 소리가 꺼져 있으면 **음성 합성을 호출하지 않는다**(비용 절약).
- 음성 재생이 실패하면(자동재생 차단, 호출 실패) 자동으로 텍스트만 보여 준다. 화면이 멈추지 않는다.

## 화면 인식 (웹)

비용을 아끼기 위해 **로컬에서 먼저 거르고** 필요할 때만 모델을 호출한다.

1. 공유된 화면을 약 2초마다 640px 폭으로 샘플링한다(캔버스).
2. 직전 프레임과 해시·픽셀 차이를 비교해 **같은 화면 체류 시간**을 로컬에서 계산한다(무료).
3. 규칙 게이트를 통과(체류 20초 이상 등)한 순간에만 프레임 1장을 Haiku 비전에 보낸다.
4. 수락 후 실행 단계에서만 Sonnet(또는 라우터가 고른 Opus)을 호출한다.
5. **세션당 비전 호출 상한**을 둔다(예산 보호).

### 공유 방식과 안내

- `getDisplayMedia`로 **창 또는 탭 하나만** 공유하게 안내한다. 전체 화면 공유는 권하지 않는다.
- 우리 사이트가 **데모용 가짜 메일 화면**을 제공하고, 심사자는 그 탭을 공유한다.
- **Chrome 권장**: 첫 화면과 공유 시작 전 안내 문구에 "Chrome에서 열어 주세요"를 명시한다. 브라우저별 지원 차이가 있으므로 구현 시 실제로 확인한다.
- 공유를 지원하지 않거나 거절하면 **스크립트 장면 모드**로 전환해 데모가 끝까지 돈다(AC-8).
- 웹은 활성 창 제목을 얻을 수 없다. 장면 구분은 프레임 내용(비전)에 의존한다.
- 캡처 이미지는 서버에 저장하지 않고 요청 처리 후 폐기한다.

### 공유 중 표시

- 화면을 가리지 않도록 **오른쪽 하단**에 작은 표시기로 둔다(예: 점 + "공유 중" 텍스트).
- 표시기를 누르면 공유를 중지할 수 있다. 중지는 항상 한 번의 클릭으로 가능해야 한다.
- 표시기는 캐릭터·확인 카드·공유 대상 데모 화면의 주요 영역과 겹치지 않는 위치를 유지한다(오른쪽 하단이 겹치면 디자인에서 조정).

## 크레딧 예산

- 이 프로젝트는 **김유빈 계정의 API 크레딧(인당 $500, 행사 내 사용만)**을 사용하며, 개발과 시연 모두 이 PC에서 이 키로 호출한다.
- 그중 **$150는 시연·테스트용으로 예약**하고 개발 중에는 손대지 않는다. 개발·디버깅에 쓸 수 있는 금액은 약 $350다.
- 비전 호출은 비용이 빠르게 늘 수 있으므로 세션당 상한과 일일 상한을 둔다. 개발 중 잔액을 수시로 확인하고, 남은 금액이 $150에 가까워지면 호출을 멈춘다.
- 공개 링크로 심사자가 쓰는 호출도 같은 키에서 차감되므로, 예약분 $150이 심사 중 소진되지 않게 서버의 일일 상한을 그 금액 이하로 설정한다.
- ElevenLabs는 Anthropic 크레딧으로 결제되지 않는다. 별도로 확인한다.
- Anthropic 키는 이 PC의 프로젝트 `.env`(레포에 커밋되지 않음)와 Vercel 환경변수에만 둔다.

## 합격 기준

- AC-1: 장면 A에서 20초 후 캐릭터가 말을 건다
- AC-2: 타이핑 중인 장면에서는 말을 걸지 않는다
- AC-3: 하루 3회를 넘기면 말하지 않는다
- AC-4: 확인 카드를 수락해야만 초안이 저장된다
- AC-5: 거절하면 아무것도 저장되지 않는다
- AC-6: 발송·삭제 도구는 코드에 존재하지 않는다
- AC-7: 웹 링크가 로그인 없이 열리고 90초 데모가 끝까지 돈다
- AC-8: API 실패나 화면 공유 불가 시 준비된 대사·스크립트 장면으로 폴백하고 화면이 멈추지 않는다
- AC-9: 공유 중 표시기가 오른쪽 하단에 있고 한 번의 클릭으로 공유를 중지할 수 있다
- AC-10: 브라우저에 API 키가 노출되지 않는다(모든 호출이 서버 프록시 경유)
- AC-11: 잡담·심심해서 부르는 요청은 Sonnet·Opus를 호출하지 않고 미리 만든 애니메이션으로 응답한다
- AC-12: 업무 요청(초안, 일정)은 잡담으로 오분류되지 않고 정상적으로 수행된다
