## 한 줄 정의

일하는 동안 옆에서 눈치껏 한마디 하고, 시킨 일은 초안까지 해두는 캐릭터.

컴패니언은 정은 있지만 일을 못 하고, 에이전트는 일은 하지만 정이 없다. 캐릭터가 일의 맥락을 읽는 능력(눈치)으로 정을 만든다. 연애·성인 요소 없음, 일 잘하는 같은 팀 동료.

## 제품 형태

- **웹(심사 링크)**: 링크만 열면 데모가 완결된다. 웹은 브라우저 제약상 바탕화면 위 투명 오버레이가 불가능(Document PiP는 타이틀바 고정·크기 상한·창 1개·투명도 미지원)하므로, 가짜 데스크톱 위에 캐릭터를 띄운다.
- **데스크톱 상주 앱(제품 증명)**: 투명·항상 위·클릭 통과 오버레이. 결선 발표는 이 앱으로 시연한다.
- **서버(`/api`)**: Claude, ElevenLabs, 눈치 게이트, 데모 계정 커넥터. 키와 토큰은 서버에만 둔다.
- 화면 맥락: 웹은 `getDisplayMedia`(사용자가 고른 탭·창 하나), 데스크톱은 활성 창 + 허용된 캡처. 자세한 내용은 아래 "화면 인식".

### 스택 결정: AIRI 포크 시험 (시간 제한)

[moeru-ai/airi](https://github.com/moeru-ai/airi)를 직접 확인한 결과:

- 라이선스 MIT, TypeScript pnpm 모노레포, 오늘도 커밋이 올라오는 활성 프로젝트
- `apps/stage-web`(브라우저)와 `apps/stage-tamagotchi`(Electron 데스크톱)가 이미 있다
- README 기준 Live2D·VRM 지원, `pnpm dev`로 실행

포크하면 캐릭터 표시·감정 매핑·음성·LLM 연결과 **데스크톱 오버레이까지** 얻으므로 Tauri 셸을 직접 만들 필요가 없다(Tauri 대신 AIRI의 Electron 사용). 반면 레포가 약 590MB로 크고, 당일 파악 비용이 든다.

**시험 기준**: 얕은 클론(`git clone --depth 1`) 후 `pnpm i && pnpm dev`로 stage-web이 **30~40분 안에** 뜨면 포크로 진행하고, 못 뜨면 즉시 접고 Next.js + `pixi-live2d-display` 직접 구현으로 돌아간다.

미확인: Claude·ElevenLabs 내장 여부, 웹판의 실제 동작 범위, 화면 인식 유무(문서에 언급 없음), 빌드 난이도. 시험 때 확인한다.

포크 시 제출물과 발표에 "AIRI(MIT) 기반, 눈치 엔진·업무 도구·확인 UX·데모 계정 연동은 자체 구현"이라고 밝힌다.

## 눈치 엔진

입력: 활성 앱 종류, 같은 화면 체류 시간, 화면 텍스트 요약과 언어, 마지막 끼어들기 후 경과 시간, 오늘 끼어든 횟수.

1. **규칙 게이트(결정적, LLM 호출 전)**: 하루 3회 초과, 마지막 끼어들기 후 10분 이내, 같은 화면 체류 20초 미만, 사용자가 "조용히" 설정, 사용자 발화·타이핑 중이면 침묵
2. **판단(Haiku, 짧은 JSON)**: `{speak, reason, line, offer}`
3. **실행(Sonnet tool use)**: 사용자가 확인 카드를 수락한 경우에만

## 90초 데모

| 시간 | 장면 |
|---|---|
| 0–10초 | 문제 제시, 캐릭터 등장 |
| 10–30초 | 영어 메일을 읽는 사용자, 캐릭터는 곁눈질, 말은 안 함 |
| 30–50초 | 20초 후 "답장 초안 써 줄까?" → 확인 카드 |
| 50–70초 | 초안 저장, "발송은 네가 직접 해" |
| 70–85초 | "오후 3시 미팅이랑 겹쳐" 충돌 경고 |
| 85–90초 | 호감도 상승, 해금될 의상 예고, 로드맵 한 줄 |

타이핑 중 침묵하는 장면을 하나 반드시 넣는다(눈치를 가장 잘 보여준다).

## 화면 인식

웹과 데스크톱 모두에서 "보기"가 동작해야 하며, 비용을 아끼기 위해 **로컬에서 먼저 거르고** 필요할 때만 모델을 호출한다.

1. 공유된 화면을 약 2초마다 640px 폭으로 샘플링한다(캔버스).
2. 직전 프레임과 해시·픽셀 차이를 비교해 **같은 화면 체류 시간**을 로컬에서 계산한다(무료).
3. 규칙 게이트를 통과(체류 20초 이상 등)한 순간에만 프레임 1장을 Haiku 비전에 보내 `{speak, reason, line, offer}`를 받는다.
4. 수락 후 실행 단계에서만 Sonnet을 호출한다.

- 웹: `getDisplayMedia`로 **창 또는 탭 하나만** 공유하도록 안내한다. 전체 화면 공유는 권하지 않는다. 심사자에게는 우리가 띄운 데모 메일 탭을 고르게 한다.
- 데스크톱: 활성 창 제목 + 허용된 캡처. 결선 발표에서는 전체 화면 인식을 시연해도 된다.
- 웹은 활성 창 제목을 얻을 수 없다. 장면 구분은 프레임 내용(비전)에 의존한다.
- 캡처 이미지는 서버에 저장하지 않고 요청 처리 후 폐기한다.

## 감정과 캐릭터

감정 6종: neutral, happy, thinking, surprised, sorry, focused. 모델의 표정·모션 이름은 매핑 파일에서 연결한다. Live2D 샘플 모델의 공개 배포 라이선스는 확인 필요. 11:45까지 렌더링이 안 되면 2D 스프라이트 표정 교체로 폴백한다.
