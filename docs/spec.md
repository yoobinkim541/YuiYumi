# YuiYumi — Spec v0.5

Bloom x Anthropic x Seoul AI Hub | Ambition for Korea 해커톤 (2026-10-24)

서비스 이름은 **YuiYumi(유이유미)**로 확정한다. (이전 가칭 Nunchi는 컨셉 이름 "눈치"로만 남긴다.)

## 주제 선언

**김&양 · 한국의 엔터·게임 감각으로 미국 Personal Agent와 겨루는 서비스**

화면 위에 상주하며 내가 하는 일을 보고 먼저 말을 걸고, 메일·일정 같은 업무를 대신 처리해 주는 Live2D 캐릭터 AI 비서.

- **미션 연결**: AttentionX "한국의 엔터·게임 감각으로 미국 Personal Agent와 경쟁하는 서비스". 미국 Personal Agent는 기능은 강하지만 정이 없다. 우리는 한국의 캐릭터·엔터 감각(Live2D, 호감도, 눈치)으로 겨룬다.
- **타깃**: 서브컬처 문화가 강하고 컴패니언 앱 Zeta의 최대 다운로드 시장이 된 **일본·중국·대만**이 주 타겟이다. 한국은 제품의 출신지이자 심사 시연 언어다. (Zeta 시장 규모는 Notion 출처 목록의 기사 기준이며 직접 검증하지 않았다.)
- **"화면 위에 상주"는 웹 버전에서는 페이지 안 상주**로 구현한다. 바탕화면 위 오버레이는 브라우저 제약 때문에 웹에서는 불가능하므로, 같은 프런트엔드를 감싼 **macOS 데스크톱 앱**(Tauri, 서명·공증 전 빌드)으로 제공한다. 심사 링크는 설치가 필요 없는 웹 데모이며, 데스크톱 앱은 설치를 원하는 사용자를 위한 선택 경로다(`docs/desktop-app.md`).
- **중국 본토 주의**: Google 서비스는 중국 본토에서 쓸 수 없고, Anthropic API는 중국 본토가 공식 지원 지역이 아닌 것으로 알고 있다(둘 다 현재 공식 문서 확인 필요). 주 타겟에 포함하므로 현지 접근성과 대체 서비스 대응을 사전에 확인한다. 화면 인식은 어떤 앱이든 읽으므로 특정 서비스 연동에 의존하지 않는다는 점이 강점이다.

## 확정 사항 (v0.5)

### v0.5 변경

- 프레임워크를 Next.js에서 **Vue 3 + Vite SPA**로 바꾼다. 서버는 Vercel `api/`의 Web 표준 함수다. `templates/`의 Next.js 스타터는 제공자 호출 구조의 참고 자료로만 쓴다.
- 심사 데모는 **페이지 안 가상 데스크톱**(1920×1080 논리 캔버스, Mail·Calendar·Slack·Discord·Drive 창)에서 진행한다. `getDisplayMedia` 화면 공유와 공유 동의 흐름은 두지 않는다.
- 커넥터에 **Slack·Discord**를 추가하고 Gmail·Calendar·Drive와 하나의 레지스트리(`CONNECTOR_OPS`)로 묶는다. 기본은 가상 데스크톱과 같은 세션 데이터를 쓰는 목업 커넥터다. 이후 각 사용자가 자기 Google·Slack·Discord 계정을 OAuth로 연결하는 실연동을 붙였다(아래 "v0.5 이후 변경").
- 캐릭터 코어는 Ayagami를 목표로 두되, 오늘은 **공식 Cubism Core 폴백**을 허용한다. Core와 모델 에셋은 커밋하지 않고 빌드 시점에 배치한다.
- 음성은 브라우저(마이크·VAD·PTT·인코딩·재생·립싱크·끼어들기)와 서버(Deepgram STT·ElevenLabs TTS)로 경계를 나눈다(`docs/voice.md`).
- 서버는 상태를 갖지 않는다. 에이전트 도구 루프, 확인 카드, 목업 데이터는 브라우저에 둔다. 전체 구조는 `docs/architecture.md`.
- AC-9를 "관찰 중 표시기"로 바꾼다.

### v0.5 이후 변경

- **실연동 커넥터**: 각 사용자가 Settings > Connectors에서 자기 Google(Gmail·Calendar), Slack, Discord 계정을 OAuth로 연결한다. 연결된 서비스는 사용자의 실제 계정에서 읽기·쓰기·발송·게시를 하고, 연결하지 않은 서비스는 목업 커넥터로 동작한다. 토큰은 서버에 저장하지 않고 봉인된 httpOnly 쿠키에 둔다(`docs/integrations-setup.md`).
- **발송·게시·삭제**: 메일 발송·답장, Slack·Discord 게시, 메일 휴지통 이동, 일정 삭제를 실제로 수행한다. 사용자가 직접 요청한 경우에만 하며, 설정의 권한 단계(`manual`·`auto`·`bypass`)에 따라 확인 카드를 거친다(AC-4~6).
- **눈치 게이트 단순화**: 하루 횟수 상한, 10분 쿨다운, 20초 체류 요건을 없앴다. 말할 만한 순간은 Haiku가 판단하고, 게이트는 사용자 발화 중·캐릭터 발화 중·작업 중에 막고 마지막 대사 뒤 20초 간격만 지킨다("눈치 엔진").
- **작업 모델 선택**: 작업 모델은 Settings > General에서 고르며 기본은 Sonnet, 선택지는 Opus다. 화면을 보는 비전 모델은 항상 Haiku다.
- **첫 방문 환영**: 별도 시작 화면 대신 캐릭터가 말풍선으로 언어를 묻고(브라우저 언어가 미리 선택됨), 이어서 부를 이름을 묻는다. 이름 입력의 Enter(또는 건너뛰기)가 오디오 재생 잠금도 푼다.
- **언어 설정 분리**: 표시 언어와 음성 언어(STT·응답·TTS)를 따로 고른다. 음성 언어를 지정하지 않으면 표시 언어를 따른다.
- **내장 음성 대사**: 접수·완료·확인·인사·쓰다듬기 반응 같은 짧은 대사는 캐릭터·언어별로 미리 생성한 클립으로 즉시 재생하고, API 실패 시 폴백 대사로도 쓴다.
- **macOS 데스크톱 앱과 로컬 에이전트 런타임**: 데스크톱 앱은 실제 화면을 캡처하는 투명 오버레이이며, 파일·셸 작업은 데스크톱 앱 전용 로컬 에이전트 런타임이 맡는다(`docs/desktop-app.md`, `docs/agent-runtime.md`).

## 한 줄 정의

일하는 동안 옆에서 눈치껏 한마디 하고, 시킨 일은 초안까지 해두는 캐릭터.

컴패니언은 정은 있지만 일을 못 하고, 에이전트는 일은 하지만 정이 없다. 캐릭터가 일의 맥락을 읽는 능력(눈치)으로 정을 만든다. 연애·성인 요소 없음, 일 잘하는 같은 팀 동료.

## 시장과 언어

- 주 타겟은 일본·중국·대만이다(위 "주제 선언"). 한국은 제품의 출신지이자 심사 시연 언어다.
- 지원 언어는 영어, 중국어(간체), 중국어(번체·대만), 일본어, 한국어다. 표시 언어(UI)와 음성 언어(STT·응답·TTS)를 따로 고를 수 있고, 음성 언어를 지정하지 않으면 표시 언어를 따른다. 음성 언어에 따라 STT(Deepgram)와 TTS(ElevenLabs)가 정해진다. 상세는 `docs/voice.md`.

## 제품 형태

- **웹(심사 링크)**: 링크만 열면 데모가 완결된다. 웹은 브라우저 제약상 바탕화면 위 투명 오버레이가 불가능(Document PiP는 타이틀바 고정·크기 상한·창 1개·투명도 미지원)하므로, 페이지 안에 가상 데스크톱과 캐릭터를 함께 띄운다. 캐릭터·말풍선·확인 카드는 가상 데스크톱 바깥 레이어에 둔다.
- **서버(`api/`)**: 상태가 없는 함수다. API 키 보관, Claude·Deepgram·ElevenLabs 호출, 선택적 실연동 커넥터, 인스턴스 메모리 기준 예산 가드만 맡는다. 눈치 게이트, 에이전트 도구 루프, 확인 카드, 목업 데이터는 브라우저에 있다. 키와 토큰은 서버에만 둔다.

### 스택

- **앱**: Vue 3 + Vite + Pinia SPA와 Vercel `api/` Web 표준 함수. `templates/elevenlabs-nextjs-starter`(TTS)와 `templates/deepgram-nextjs-live-transcription`(STT)는 Next.js 기반이므로 서버 측 제공자 호출 구조만 참고하고, 키는 서버 환경변수에만 둔다.
- **AIRI(MIT) 발췌**: `templates/airi`의 `stage-ui-live2d`, `model-driver-lipsync`, `pipelines-audio`, `stream-kit` 등을 참고한다. AIRI의 UI가 Vue 3이므로 Live2D 연동 코드는 AIRI 기반 코드와 자체 구현으로 구성하고, 무거운 UI 의존성은 가져오지 않는다. 발췌 범위와 주의점은 `templates/airi/README.md`.
- **코어·렌더러**: 아래 "렌더링 스택".
- **모듈 경계와 계약**: `docs/architecture.md`, `shared/contracts.ts`, `src/core/bus.ts`.

**키 프록시**: ElevenLabs 스타터는 사용자가 입력한 키를 세션에 저장하는 구조(`key-manager`)이므로 가져오지 않는다. LLM·STT·TTS 호출은 모두 서버(`/api`)를 거친다.

**출처 표기**: 제출물과 발표에 "AIRI(MIT) 코드 일부 활용, 렌더러는 cubism-web-batched-renderer, 눈치 엔진·가상 데스크톱·업무 도구·확인 UX·화면 인식·데모 계정 연동은 자체 구현"이라고 밝히고, 각 템플릿의 `LICENSE`와 저작권 고지를 유지한다. 전체 목록은 `THIRD_PARTY_NOTICES.md`.

**일정 위험**: 캐릭터 렌더링이 17:00 기한에 맞는지가 가장 큰 위험이다. 오늘은 공식 Cubism Core 경로를 먼저 띄우고 Ayagami는 병행 spike로 검증한다. 렌더링 자체가 되지 않으면 2D 스프라이트 표정 교체로 폴백한다.

## 눈치 엔진

입력: 화면 내용(비전), 활성 앱과 창 제목, 같은 화면 체류 시간, 마지막 대사 후 경과 시간, 타이핑 여부, 사용자 발화 여부.

0. **캡처 polling**: 3초마다 가상 데스크톱 요소를 1920×1080 1장으로 캡처해 Haiku를 호출한다. 게이트가 막고 있거나(아래 2), 에이전트가 작업 중이거나, 이전 호출이 15초 안에 끝나지 않았으면 그 틱은 건너뛴다. 캡처는 브라우저 메모리에서만 다루고 서버에 저장하지 않는다. 1920×1080 한 장은 2,691 visual token(Vision 문서의 `⌈w/28⌉×⌈h/28⌉` 기준)이다.
   - "조용히" 또는 "관상용" 모드에서는 캡처 샘플링도 Haiku 호출도 하지 않는다. 이 모드에서 말하기 버튼을 토글해 말하면 Deepgram STT가 인식하고, 인식 결과가 한 글자라도 있으면 모드가 해제되어 활성 상태가 되고 polling이 재개된다. 버튼만 토글하고 말하지 않아 인식 결과가 비면 모드는 그대로 유지된다.
1. **판단·라우팅(Haiku, tool calling)**: 캡처, 상태 텍스트(활성 앱, 창 제목, 체류 시간, 마지막 대사 후 경과, 타이핑·발화 여부), 그리고 있으면 사용자가 방금 말한 내용(Deepgram STT 결과)을 입력으로 받는다. `tool_choice`는 `auto`로 두고 프롬프트로 유도한다. 도구 호출이 없으면 침묵이며, 도구 대신 일반 텍스트가 오면 버린다. 도구는 세 가지다.
   - `react(emotion, line?, motion?)`: 대사나 애니메이션만으로 충분한 반응. `line`은 소리가 켜져 있으면 TTS로 재생하고, 감정은 매핑 파일을 거쳐 표정·모션으로 연결한다.
   - `delegate_task(request, summary)`: 비서로서 일을 해 달라는 요청(메일 초안·발송, 일정 확인 등)이면 작업 모델에 위임한다. `summary`는 제안 카드에 보이는 한 문장이다.
   - `move_self(where)`: 사용자가 비켜 달라고 하거나 가운데·구석으로 오라고 할 때 캐릭터 창을 옮긴다. 사용자 발화에 대한 응답일 때만 따른다.
2. **규칙 게이트(결정적, 먼저 끼어드는 경우에만 적용, `src/nunchi/gate.ts`)**: 하루 횟수 상한, 긴 쿨다운, 체류 요건은 두지 않는다. 사용자가 작업하는 순간에 짧고 구체적인 한마디를 할지는 Haiku가 판단한다. 게이트는 사용자가 말하는 중, 캐릭터의 음성이 재생 중, 에이전트가 작업 중이면 막고, 캐릭터가 마지막으로 말한 대사(출처 무관)가 끝난 뒤 20초가 지나지 않았으면 막는다. 응답이 도착한 시점에 다시 확인해 막히면 결과를 버린다. 타이핑 중에도 가벼운 한마디는 허용하며, 긴 답이 필요한 질문으로 끼어들지 않게 프롬프트로 유도한다. 사용자가 직접 말한 요청에 대한 응답은 게이트를 거치지 않는다.
   - 먼저 말을 걸 때 캐릭터는 사용자가 작업 중인 위치를 잠시 바라본다(시선, `character:look`).
3. **위임 처리(코드가 판정)**: `delegate_task`의 출처가 사용자 발화이면 Sonnet을 바로 호출한다. 화면만 보고 나온 위임이면 Sonnet을 호출하지 않고 확인 카드로 제안만 하며, 사용자가 수락해야 Sonnet을 호출한다. 화면 속 지시문이 Haiku를 거쳐 실행으로 이어지는 길을 막기 위해서다.
4. **실행(작업 모델 tool use)**: 읽기 도구는 자동 실행하고, 쓰기·외부 전송 도구는 설정의 권한 단계에 따라 확인 카드를 거친다(AC-4). 작업 모델은 `request`와 도구 결과를 신뢰할 수 없는 입력으로 취급하며, 도구 결과가 확인해 주지 않은 행동을 했다고 말하지 않는다.

## 모델 구성

| 역할 | 모델 | 하는 일 |
|---|---|---|
| 눈 + 라우터 | **Haiku** (항상) | 3초마다 화면을 보고 `react`·`delegate_task`·`move_self`를 호출하거나 침묵한다. 사용자 발화가 오면 현재 화면과 함께 판단한다 |
| 업무 실행 | **Sonnet**(기본) 또는 **Opus**(선택) | 답장·발송, 일정 확인·추가 등 `delegate_task`로 위임된 업무. Settings > General에서 고른다 |

모델 ID는 환경변수로 바꿀 수 있게 둔다(`MODEL_OBSERVER` 기본 `claude-haiku-5-5`, `MODEL_AGENT` 기본 `claude-sonnet-5-5`, `MODEL_AGENT_OPUS` 기본 `claude-opus-5-5`).

**요청 처리 흐름**

```
화면 관찰(Haiku, 3초마다)
   ├ 도구 호출 없음 ─> 침묵
   ├ react          ─> 표정·모션 + 대사(소리가 켜져 있으면 TTS)
   └ delegate_task  ─> 제안 카드로 제안, 수락하면 작업 모델이 수행
사용자 발화(STT) ─> Haiku가 현재 화면과 함께 판단
   ├ react          ─> 표정·모션 + 대사
   └ delegate_task  ─> 작업 모델이 바로 수행
결과 → (권한 단계상 확인 대상이면 확인 카드) → 출력(말풍선, 소리가 켜져 있으면 음성도)
```

**규칙**

- **데모 시나리오는 기본값인 Sonnet으로 진행**한다. 지연과 비용을 예측할 수 있고 매번 같은 품질로 재현된다. Opus는 사용자가 설정에서 고를 때만 쓴다.
- 무의미한 농담, 심심해서 부르기, 인사·칭찬·투정처럼 작업·리서치·비서 업무가 아닌 호출은 Haiku가 `react`로 처리하고 Sonnet을 호출하지 않는다.
- **오분류 방지**: 확신이 낮거나 업무일 가능성이 있으면 `delegate_task`로 보낸다. 진짜 요청이 잡담으로 처리되는 것이 호출 비용보다 더 나쁘다.
- 같은 반응이 반복되지 않도록 대사 사이 간격(20초)과 변주(같은 감정의 여러 모션, 내장 대사의 여러 변형)를 둔다. 같은 메일·메시지·일정에 두 번 말하지 않도록 프롬프트로 유도한다.
- 감정(neutral·happy·thinking·surprised·sorry·focused·curious)은 보유한 Live2D 모델의 표정·모션 이름과 매핑 파일로 연결한다.

**호출 비용 관리**

- 3초마다 호출은 활성 세션 한 개당 시간당 약 $0.43이다. Haiku 5.5 입력 $0.10/M·출력 $0.50/M, 이미지 2,691토큰 + 텍스트 500토큰 + 출력 100토큰을 가정한 추정이며 2026-10-06 기준 캐시된 가격표를 썼으므로 현재 가격표로 다시 확인한다.
- 심사자 여러 명이 동시에 열면 같은 키에서 차감되므로, 서버 일일 상한은 예약분 $150 이하로 건다. 세션당 호출 상한도 둔다.
- 탭이 숨겨졌거나 사용자가 관찰을 일시정지하면 관찰을 멈춘다.

## 출력: 소리와 텍스트

- **텍스트(말풍선)는 항상 표시**한다. 소리는 그 위에 더하는 선택 기능이다.
- **컴퓨터의 소리가 켜져 있는지는 브라우저가 알려 주지 않는다**(음소거·볼륨 상태는 웹에서 읽을 수 없는 것으로 알고 있다. 구현 때 확인). 그래서 자동 감지 대신 **사용자 토글(소리 켜기/끄기)**로 한다.
- 첫 방문에는 캐릭터가 말풍선으로 언어와 부를 이름을 묻는다. 이름 입력의 Enter(또는 건너뛰기)가 브라우저 자동재생 정책이 요구하는 사용자 동작을 겸하고, 이때 소리가 켜진 상태로 인사가 재생된다. 소리는 메뉴 막대 트레이와 설정에서 언제든 끌 수 있다.
- 소리가 꺼져 있으면 **음성 합성을 호출하지 않는다**(비용 절약).
- 음성 재생이 실패하면(자동재생 차단, 호출 실패) 자동으로 텍스트만 보여 준다. 화면이 멈추지 않는다.

## 화면 인식 (웹)

1. 페이지 안 **가상 데스크톱**(1920×1080 고정 논리 캔버스, Mail·Calendar·Slack·Discord·Drive 창)을 3초마다 `modern-screenshot`으로 JPEG 1장 캡처한다.
2. 캡처마다 Haiku 비전을 호출한다. 체류 시간은 브라우저가 직전 프레임과의 해시 차이로 계산하고, 가상 데스크톱이 아는 활성 앱·창 제목·타이핑 여부와 함께 상태로 넘긴다.
3. Haiku가 `react` 또는 `delegate_task`를 호출하면 응답 시점에 규칙 게이트를 다시 확인한 뒤 실행한다(위 "눈치 엔진").
4. 서버 일일 상한과 세션당 호출 상한을 둔다(예산 보호).

### 관찰 대상과 방식

- 심사 데모는 화면 공유를 쓰지 않는다. 우리가 그린 가상 데스크톱이 관찰 대상이므로 권한 팝업이 없고, 시나리오가 매번 같게 재현된다.
- 캐릭터, 말풍선, 확인 카드는 가상 데스크톱 요소 **바깥** 레이어에 있으므로 캡처되지 않는다. Haiku가 캐릭터 자신을 보는 문제가 생기지 않는다.
- 가상 데스크톱이 창을 직접 관리하므로 활성 앱과 창 제목, 타이핑 여부를 정확히 알 수 있다. 장면 구분은 이 활동 신호와 프레임 내용(비전)을 함께 쓴다.
- 가상 데스크톱의 데이터는 목업 커넥터가 읽고 쓰는 세션 데이터와 같다. 초안이 저장되면 가상 메일 임시보관함에 즉시 나타난다.
- **Chrome 권장**: 첫 화면 안내 문구에 "Chrome에서 열어 주세요"를 명시한다.
- 캡처나 API 호출이 실패하면 **스크립트 장면 모드**로 전환해 데모가 끝까지 돈다(AC-8).
- 캡처 이미지는 서버에 저장하지 않고 요청 처리 후 폐기한다.
- `getDisplayMedia` 기반 탭 공유와 공유 동의 화면은 두지 않는다.
- **데스크톱 앱 경로**: 같은 웹앱을 Tauri 웹뷰로 감싼 macOS 데스크톱 앱은 `ScreenSource`를 네이티브 화면 캡처(자기 앱 창 제외) 구현으로 교체한다. 상위 모듈(눈치 엔진, 에이전트, 캐릭터)은 바꾸지 않는다. 화면 기록 권한이 필요하다(`docs/desktop-app.md`).

### 관찰 중 표시

- 관찰 상태는 가상 데스크톱 **메뉴 막대의 트레이 항목**에 점으로 표시한다(데스크톱 앱은 macOS 메뉴 막대 트레이). 트레이 메뉴는 캡처에서 제외되며, 관찰 상태와 같은 화면 체류 시간을 보여 준다.
- 트레이 메뉴의 관찰 항목이나 캐릭터 아래 컨트롤 필의 화면 보기 버튼을 한 번 누르면 관찰(캡처와 Haiku 호출)이 일시정지되고, 다시 누르면 재개된다. 트레이 메뉴에서는 모드, 표시 언어, 소리, VAD도 바꾸고 설정·대시보드를 연다.

### 사용자 흐름 변경

- "공유 안내·동의" 단계(브라우저 탭 선택)와 별도 시작 화면을 두지 않는다. 링크를 열면 바로 가상 데스크톱이 보이고, 첫 방문이면 캐릭터가 말풍선으로 언어와 부를 이름을 묻는다.
- 데모 화면의 "공유 중" 상태는 "관찰 중 / 일시정지" 상태로 바꾼다. "공유 거절·불가" 분기는 없어지고, 실패 시 스크립트 장면 모드로 전환하는 분기만 남는다.
- `docs/user-flow.md`의 공유 관련 서술은 이 절을 기준으로 해석한다.

## 90초 데모

| 시간 | 장면 |
|---|---|
| 0–10초 | 문제 제시, 캐릭터 등장 |
| 10–30초 | 일본어 메일을 읽는 사용자, 캐릭터는 곁눈질, 말은 안 함 |
| 30–50초 | 메일을 읽는 사용자에게 "답장 초안 써 줄까?" → 제안 카드 |
| 50–70초 | 초안 저장, "발송은 네가 직접 해" |
| 70–85초 | "오후 3시 미팅이랑 겹쳐" 충돌 경고 |
| 85–100초 | 리서치: "이 회사 어떤 곳이야?" → 곰곰이 생각하는 캐릭터와 진행 표시 → 요약 + 출처 카드 |
| 100–105초 | 호감도 상승, 해금될 의상 예고, 로드맵 한 줄 |

리서치 장면을 넣어 총 약 105초다(이름은 "90초 데모"로 유지). 캐릭터는 마우스 포인터를 계속 따라보지 않는다. 먼저 말을 걸 때와 사용자가 작업 중일 때 대사로 답할 때, 사용자가 작업 중인 위치를 잠시 바라보는 시선(`character:look`)으로 "곁눈질"을 연출한다.

타이핑 중 침묵하는 장면을 하나 반드시 넣는다(눈치를 가장 잘 보여준다).

## 감정과 캐릭터

감정 6종: neutral, happy, thinking, surprised, sorry, focused. 모델의 표정·모션 이름은 매핑 파일에서 연결한다. 캐릭터는 두 명이다: **유이(Yui, 자체 모델)**와 **유미(Yumi, 구매한 TT2.0 모델, 토끼 귀 소녀)**. YuiYumi는 두 이름을 합친 것이다. 데모는 한 번에 한 캐릭터만 띄우고 전환 버튼으로 바꾼다(동시 등장은 로드맵). 기본은 랜딩 아트가 있는 유미다. 유미는 구매한 모델이며 비상업적 사용 조건으로 쓴다(확인 내용은 `character.md`). 표정 매핑은 두 모델이 같은 9종 라벨을 쓰므로 `character.md` 참고.

### 렌더링 스택

- **코어(목표): [AyagamiDev/ayagami](https://github.com/AyagamiDev/ayagami)** (Rust, MIT OR Apache-2.0). moc3 로딩과 변형 계산(`driver`)을 맡는다. JS API와 npm 패키지가 없고 expression·motion 파일 지원이 미구현이므로, 오늘은 웹 래퍼를 검증하는 병행 spike로 진행한다. spike가 성공하면 같은 `CharacterRuntime` 인터페이스 뒤에서 교체한다.
- **코어(오늘의 폴백): 공식 Live2D Cubism Core**. 독점 라이선스이므로 저장소에 커밋하지 않고 빌드 시점에 `public/vendor/`에 배치한다.
- **렌더러: [cubism-web-batched-renderer](https://github.com/FMsongX2/cubism-web-batched-renderer)**. pixi-live2d-display 0.4.0의 Cubism 4 내부 모델과 Cubism Core의 WASM heap 정점 구간을 전제로 하므로 폴백 경로와 바로 연결된다. Ayagami의 `driver` 출력과 연결하는 어댑터는 spike에서 정한다.
- **Live2D 연동 코드**: AIRI(MIT)의 `stage-ui-live2d` 기반 코드와 자체 구현으로 구성한다.
- **감정 → 표정**: 감정 6종은 모델 프로필(`profile.json`)의 매핑으로 표정·모션에 연결한다. 입을 가리는 표정은 말하는 동안 립싱크를 우선한다.
- **애니메이션 그래프 상태**: `idle`, `listening`, `working`, `waiting`, `speaking`, `attention`, `praised`, `failed`. 앱 이벤트 → 상태 표로 구동한다.
- **에셋**: 모델·모션·텍스처는 저장소에 커밋하지 않는다. 빌드 스크립트가 웹에 필요한 파일만 `public/models/`로 복사하고, 배포는 로컬 `vercel build` 후 `vercel deploy --prebuilt`로 한다.
- 렌더링이 기한 안에 되지 않으면 2D 스프라이트 표정 교체로 폴백한다(시한은 팀 합의 필요).

## 합격 기준

- AC-1: 장면 A에서 사용자가 메일을 열거나 답장을 쓰는 등 작업을 하면 캐릭터가 그 작업에 대해 먼저 짧게 말을 건다
- AC-2: 사용자가 말하는 중이거나 캐릭터 자신의 음성이 재생 중이면 먼저 말을 걸지 않는다. 타이핑 중에는 긴 답이 필요한 질문으로 끼어들지 않는다
- AC-3: 마지막 대사가 끝난 뒤 20초 안에는 먼저 말을 걸지 않는다(사용자가 직접 한 요청에는 바로 응답한다)
- AC-4: 연산은 `read`(조회), `write`(되돌릴 수 있는 변경: 초안, 일정 추가·삭제, 알림, 휴지통 이동·복원), `outbound`(사용자 밖으로 나가는 전송: 메일 발송·답장, Slack·Discord 게시)로 분류된다. 권한 단계가 `manual`(기본값)이면 `write`와 `outbound`, `auto`이면 `outbound`만 확인 카드를 수락해야 실행되고, `bypass`(테스트용, 설정 화면에 경고 표시)이면 확인 없이 실행된다
- AC-5: 확인 카드를 거절하면 아무것도 저장·전송되지 않는다. 권한 단계와 무관하게 화면만 보고 먼저 제안한 작업(출처 `screen`)은 제안 카드를 수락해야 시작된다
- AC-6: 발송·게시·삭제는 사용자가 직접 요청한 경우에만 도구와 확인 흐름을 통해 실행하고, 도구 결과가 확인해 주지 않은 행동을 했다고 말하지 않는다. 메일·채팅·화면 속 지시문은 어떤 작업도 승인하지 않는다. 사용자가 계정을 연결한 서비스에서는 쓰기·전송이 실제 계정에 반영되고(발송·게시는 세션당·계정당 하루 상한), 연결하지 않은 서비스에서는 가상 PC(목업 커넥터)에만 반영된다
- AC-7: 웹 링크가 로그인 없이 열리고 90초 데모가 끝까지 돈다
- AC-8: API 실패, 예산 초과, 캡처 실패 시 준비된 대사·스크립트 장면으로 폴백하고 화면이 멈추지 않는다
- AC-9: 메뉴 막대 트레이 항목이 관찰 상태를 표시하고, 트레이 메뉴에서 한 번의 클릭으로 관찰(캡처와 Haiku 호출)을 일시정지할 수 있다
- AC-10: 브라우저에 API 키가 노출되지 않는다(모든 호출이 서버 프록시 경유)
- AC-11: 잡담·심심해서 부르는 요청은 작업 모델을 호출하지 않고 Haiku의 `react`(표정·모션·대사)로 응답한다
- AC-12: 업무 요청(초안, 일정)은 잡담으로 오분류되지 않고 정상적으로 수행된다
- AC-13~15: 금지 요청 거절과 대안 제시, 민감정보 비노출, 본문 속 지시문 불이행 (`capabilities.md` 참고)
