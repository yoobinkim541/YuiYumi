# 외부 서비스 연동: 커넥터 구조

각 서비스를 같은 인터페이스의 도구로 등록하고, 도구마다 위험 등급을 둔다.

| 서비스 | 읽기 (자동 실행) | 쓰기 (확인 카드 필수) |
|---|---|---|
| Gmail | 메일 목록·본문 | **초안 생성만** |
| Google Calendar | 일정 조회·충돌 검사 | 일정 생성 |
| Google Drive | 파일 검색·내용 읽기 | 없음 |
| Notion | 공유된 페이지·DB 읽기 | 페이지에 메모 추가 |

- 등급은 `read`와 `write` 두 가지다. `send`, `delete` 등급은 만들지 않는다.
- Google 세 서비스는 OAuth 한 번으로 묶고, Notion은 연동 토큰으로 접근한다. Notion은 공유해 준 페이지만 보이게 한다.

## 오늘의 범위

1. **필수**: 커넥터 인터페이스, 확인 카드, Gmail·Calendar 목업(JSON)
2. **시간이 남으면**: Google Calendar 읽기 실연동
3. **오늘 안 함**: Drive, Notion 실연동(인터페이스와 목업 스텁까지)

무엇이 목업인지는 제출물에 명시한다.

## 도구 (최소)

- `read_scene()`: 현재 장면 컨텍스트. 웹은 스크립트, 데스크톱은 허용된 캡처
- `draft_reply(email_id, tone)`: 초안 생성 후 저장만
- `check_calendar(date_range)`: 충돌 일정 조회, 읽기 전용

## 안전 규칙

- **Gmail 초안 권한(`gmail.compose`)은 발송 권한도 포함한다.** "발송 기능이 없다"는 권한이 아니라 **코드 수준의 보장**이며 제출물에도 그렇게 서술한다.
- 메일·Drive·Notion의 내용은 **신뢰할 수 없는 입력**이다. 본문에 지시문이 있어도 따르지 않고, 도구 결과는 데이터로만 다룬다는 규칙을 시스템 프롬프트에 명시한다.
- 쓰기 작업은 항상 확인 카드를 거치며, 거절하면 아무것도 저장하지 않는다.
- OAuth 토큰은 로컬에 두고 레포에 넣지 않는다(`.gitignore`에 토큰 파일 추가).
